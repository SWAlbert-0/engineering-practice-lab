02 / EVIDENCE

调研怎样改变判断

工程能力可以直接映射岗位

美图官方实习样本同时要求编程与基础知识，并列出测试自动化、AI用例生成与缺陷分析等工作。由此可推断，D11/D09 的工程闭环比只做模型聊天界面更有针对性。[S1]

这是一条能力需求证据，不足以代表全行业招聘规模；该岗位标注2026暑期，不作为当前可投推荐。

强模型让验证更重要

SWE-bench 的评测流程强调补丁应用和测试执行。D11 的价值应落实到可复现环境、独立验收与失败诊断。小项目不应宣称超越成熟 coding agent，应在限定场景对比同模型基线。[S3]

RAG 的难点是检索与可信输出

官方混合检索方案把不同召回与重排串联。对工艺题，材料、设备、版本和引用有效性必须和检索指标一起评估。只接向量库并不能证明准确率提升。[S4]

监控报警与质量回滚要分开

MLflow 提供模型版本管理，Evidently 对比参考/当前分布。把两类能力接起来后，仍须补真实标签、回滚门槛和服务切换验证；数据漂移本身不能代替线上准确率。[S5] [S6]

03 / METHOD

评分口径与投入假设

难度 1–5：2 为常规应用；3 为单项AI集成或完整交互；4 为多模块系统与可靠性；5 为研究、专业数据、硬件或算力约束。与老师的 A/B/C 分类分开保留。

综合分 = 20 ×（简历潜力×35% + 当前方向适配×25% + 可完成性×20% + 可验证性×20%）。四项均为1–5分，分数描述做扎实后的潜力，不代表当前demo的含金量；相差3分以内无需机械排序。

周期估算：一人每周约15小时，具备基本编程能力，包含学习、实现、评估和文档，不含论文审稿；API/GPU费用与使用量有关，未作价格承诺。团队并行可缩短日历时间，但集成和学习不会线性缩短。

要提前向老师确认：D06“至少尝试3种以上”工具的数量口径；D07“两领域”是否都要求医学；CPU微调的可接受规模；研究型题目“可投论文成果”的验收标准。原文未给出的项目范围不能自行当成已获减免。

07 / TOPIC NOTES

逐题分析：难在哪里，怎样避免普通作业感

D11 · 基于大语言模型智能体的自动化软件测试与缺陷修复系统 丁箐 · 92分

原题要求概括：仓库解析、生成单测、定位修复至少3类缺陷；≥5个开源项目验证覆盖率和检测率。

投入：难度 4/5，10–14周；CPU + 模型 API；后期 Docker。

主要风险：最容易变成通用 coding agent 的薄封装；测试变绿不等于修复正确。

做到简历级：做测试不可修改的验收门禁、独立测试、变异测试、预算与失败归因；从 Python 单语言切入。

验收证据：以固定缺陷集比较原始测试、单轮提示、受控Agent；报告解决率、回归破坏率、成本及失败样例。

评分拆解：潜力 5 / 适配 5 / 可完成 3 / 可验证 5（各5分）。

D01 · 基于 RAG 的轻量级企业工艺生成 丁箐 · 89分

原题要求概括：PDF解析、稠密+稀疏混合召回、重排、多轮对话、引用溯源、多文档人工评估。

投入：难度 3/5，8–10周；CPU；嵌入/重排模型或 API。

主要风险：缺少真实工艺文档时只能证明检索框架；错误工艺参数风险高。

做到简历级：给出页码与工序版本；拒答与参数约束；材料/设备过滤；建立工艺师审核闭环。

验收证据：留出标注问题集；比较 BM25、dense、hybrid、+rerank 的 Recall@k、MRR、引用支持率、拒答质量。

评分拆解：潜力 4 / 适配 5 / 可完成 4 / 可验证 5（各5分）。

D02 · 基于 MLOps 的全链路 AI 模型部署与监控系统 丁箐 · 87分

原题要求概括：DVC、CPU训练、MLflow注册、FastAPI容器部署、Prometheus/Grafana、CI/CD、准确率下降回滚。

投入：难度 4/5，10–14周；CPU + Docker；多服务占内存。

主要风险：堆工具却没有故障注入；数据漂移误当准确率；线上标签延迟难处理。

做到简历级：固定数据/代码/模型版本关联；灰度发布、故障注入、无标签告警与有标签回滚分离。

验收证据：复现同数据模型；注入坏发布并展示恢复时间、版本切换后的预测；记录P95延迟和资源使用。

评分拆解：潜力 5 / 适配 4 / 可完成 3 / 可验证 5（各5分）。

D09 · 基于大模型 API 的智能需求分析与用例生成工具 丁箐 · 85分

原题要求概括：≥100个开源需求样例；功能拆分、ER建议、UML/用例格式、结构校验、一致性检查、人机反馈。

投入：难度 3/5，6–8周；CPU + 模型 API。

主要风险：只做一段提示词配网页，难以超越通用聊天工具；生成格式正确但语义不完整。

做到简历级：做需求ID→规则→用例追踪矩阵、冲突检测、版本差异和人工验收；可并入D11。

验收证据：按项目分割需求集；盲评遗漏/矛盾/可执行性；记录人工修订时间，不把100条都用于调提示。

评分拆解：潜力 4 / 适配 5 / 可完成 4 / 可验证 4（各5分）。

D03 · 基于工作流的全链路 AI 检测系统 丁箐 · 76分

原题要求概括：可视化工作流、模型选择与容器部署、可扩展规则库、异常检测、MQTT设备控制。

投入：难度 4/5，10–14周；CPU推理；MQTT可模拟。

主要风险：拖拽看起来完整，但节点执行、重试、幂等、背压缺失。

做到简历级：实现 DAG 校验、可回放事件、超时重试、设备回执和断线处理。

验收证据：非法环拒绝；节点失败恢复；重复消息不重复控制；记录端到端延迟与检测误报漏报。

评分拆解：潜力 4 / 适配 4 / 可完成 3 / 可验证 4（各5分）。

D04 · 基于 CPU 的轻量级手势识别与智能家居控制 丁箐 · 64分

原题要求概括：10类手势，每类≥500张；MobileNet迁移学习；OpenVINO/ONNX加速；MQTT/HomeAssistant；验证≥20fps。

投入：难度 4/5，8–12周；摄像头；CPU迁移学习较慢。

主要风险：CPU微调不必然快；不同人、光照、背景的域偏移；连续误触发。

做到简历级：加入连续帧确认、置信度阈值、冷却时间；比较加速前后。

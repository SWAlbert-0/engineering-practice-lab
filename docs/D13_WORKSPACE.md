# D13 文献研读工作区

D13 将固定摘记演示扩展为可持久使用的文献、证据与章节工作区。页面入口为 `/demos/06-literature/`。这是本机单工作区首版；真实供应商的生成质量和跨领域盲评尚未完成。

## 操作流程

1. 建立专题，填写研究问题、纳入/排除标准与 1–4 章提纲。
2. 导入有权使用的文本型 PDF、UTF-8 TXT/Markdown，或粘贴文本。分别标注“提供的原文”“仅摘要”“阅读摘记”。标题必填；作者、年份、DOI、网址用于参考文献，不自动核验身份或抓取链接。
3. 逐篇保存纳入、排除或待定及理由。单个专题最多纳入 6 篇，未纳入材料不会进入模型任务。
4. 手工摘录，或建立阅读任务。每条证据保存文献版本、页码、Unicode 字符起止位置、逐字片段、类别、说明与核对记录。阅读器可选择文字建立摘录；重复片段必须明确起始位置。
5. 编辑方法、发现与局限，核对上下文、输入范围和实验条件。冲突或过期项可编辑重审或移除；系统不自动解决学术分歧。
6. 确认提纲，完成全部证据核对后生成章节。每篇纳入文献至少需要一条有效证据。
7. 在章节编辑区修改论述与引用，等待自动保存或手动保存，再提交新版本。版本冲突保留本地文本，可下载 JSON 后合并；自动草稿与已提交版本分开管理。
8. 在“引用核对”逐条确认支持关系。全部论述通过且无未提交草稿、来源仍有效时，发布不可变快照，导出 Markdown、BibTeX 与完整证据 JSON。

初次使用可点击“填入教学文本”。材料明确为虚构阅读摘记，不能作为真实论文或实验结果。

## 三种执行方式

| 方式 | 阅读 | 写作 | 外部调用 |
|---|---|---|---|
| 离线 | 第一页前 3 个句段作为未分类摘录，暂放方法栏 | 按证据类别编排，空类别回退已有证据 | 无；不做语义理解或综合质量承诺 |
| 单次模型 | 一次读取纳入文献 | 一次完成确认提纲的全部章节 | 每阶段最多 1 次 |
| 分工协作 | 每篇一个阅读节点，并发最多 3 | 每章一个作者节点，并发最多 2 | 最多 6 个阅读调用或 4 个写作调用 |

阅读与写作是两个独立任务，中间有人工作为门禁。引用检查使用确定性规则，不冒充独立“审稿智能体”。模型结构和引文不合格即失败，不自动回退为离线内容。任务确认提示说明输入范围和最大调用次数。

模型沿用服务端 `LAB_LLM_BASE_URL`、`LAB_LLM_MODEL`、`LAB_LLM_API_KEY`，见 [配置说明](MODEL_SETUP.md)。每次 API 超时 45 秒，任务不自动重试付费请求。未获得可靠的供应商 usage 数据，因此不显示虚构的 token 或成本。超时或取消不能保证供应商未计费。

## 数据关系与恢复

- `papers / paper_versions`：原文件字节、哈希、元数据和逐页提取文本；解析成功才切换当前版本。失败修订保留旧版本可用，旧文件可下载。
- `projects / selections / evidence`：问题协议、筛选决定、证据位置和人工结论，修改有 revision 乐观锁。
- `jobs / nodes`：持久队列、心跳、各节点输出与错误。进程重启后运行任务心跳超时标记中断，可显式重试。输入指纹和模型配置相同才复用成功节点，避免重复执行已完成的调用；失败任务不向矩阵部分写入结果。
- `drafts / draft_versions / reviews / releases`：自动草稿、不可变提交版本、逐条核对记录和发布包。人工记录人是文本署名，不等同认证身份。

资料版本、筛选、问题、提纲或证据变化会使旧草案过期。系统阻止过期草案继续提交、审核或发布；旧草案和已发布快照仍可按原来源查看和导出。发布包冻结来源、证据、论述和审核，不随当前资料改变。

使用现有 HTTP 服务与进程内 worker，不要求新框架或独立数据库服务；没有多用户权限、跨机器队列或实时共同编辑。旧 `engine.py` 和 `/api/literature` 教学基线保留，旧 LocalStorage 不自动迁移为“论文原文”。

## 运行与备份

与其余项目共用 Docker 镜像、Conda 或 venv 环境；无新增依赖。三种运行方式见 [README](../README.md)。Docker 更新：

```bash
git pull
docker compose up --build -d --wait --wait-timeout 90
```

数据为 `LAB_DATA_DIR/literature.sqlite3`，默认 `data/`，容器为 `/data/` 命名卷。在线一致性备份：

```bash
# 本地，在项目共用环境内执行
python scripts/backup_process_data.py --project literature --output backups/literature.sqlite3

# 容器：备份到命名卷，再复制出来
docker compose exec lab python scripts/backup_process_data.py --project literature --output /data/backups/literature.sqlite3
docker compose cp lab:/data/backups/literature.sqlite3 ./literature-backup.sqlite3
```

输出文件必须不存在。恢复前停止应用；将备份替换到对应数据库路径，移除该库旧的 `-wal`、`-shm` 文件，保持 UID/GID 10001 可读写，然后启动。原文件、页文本、历史版本均在备份内；恢复覆盖现有工作区，应先保存当前数据。

## 限制与评估

单文件最多 8 MiB、100 页、30 万字符；有效文献最多 100 份，全部原文件版本合计 256 MiB。单专题最多 6 篇、60 条证据；单份草案最多 40 条论述，每条引用 1–4 条证据。模型阅读文本或写作证据输入超过 24000 字时拒绝任务，不静默截断。PDF 解析复用隔离子进程，25 秒超时、POSIX 内存限制；不支持加密、扫描件 OCR、结构化公式/表格恢复。Windows 不提供 POSIX 资源限制。

当前没有学术搜索、全文自动下载、结构化参考文献解析或重复论文跨版本消歧。研究CLI已有固定跨领域公开标注子任务，已运行真实小模型子任务，整篇综述质量基准尚未完成。逐字匹配证明片段存在，不证明论述被支持；“提供的原文”是上传者声明，不自动保证全文完整。

自动化验证覆盖编码/字符位置、版本过期、去重、解析失败、筛选/证据门禁、引用拒绝、并发编辑、不可变发布、任务恢复和失败节点复用。浏览器流程使用虚构材料；模型协议用离线桩，不使用真实密钥。正式课题还需固定文献和专家证据，开展至少两个方向的盲评，对比单次模型与分工模式的覆盖度、引用支持、归纳质量、时延及供应商实际费用。

## 2026-10-20：文献对照、证据关系与写作前检查

新增专题页入口：

- **证据矩阵**：按关键词、核对状态和来源文献筛选；“并排核对”在同页展示原文上下文与Unicode高亮，可继续编辑/核对并打开完整原文。
- **文献对照**：按篇并列方法、发现和局限，保留范围、版本与状态。类别为空只提示判断是否适用，不自动补造内容。
- **证据关系**：人工选择两条当前有效、已核对的证据，记录“相互支持 / 存在分歧 / 互为补充”、条件说明和记录人。支持修订、历史查看与移除，不是自动知识图谱或语义判断。
- **写作前检查**：集中显示未核对、来源过期、未确认提纲、纳入文献无证据及过期关系等阻断项；摘要/摘记范围、元数据缺失、类别缺口为阅读提醒。结构就绪不等于内容质量合格。

关系同时固定两条证据的修订指纹，禁止自关联、跨专题、重复证据对和过期写入。证据解释、类别、核对状态或来源版本变化后，旧关系显示过期；需重新核对或移除后才能创建写作任务。关系更改也进入上下文指纹，使旧草案显示来源变化；已有发布快照保留原关系与核对历史。无关系的旧专题不增加空字段，避免升级后使所有旧草案无故过期。

模型写作可接收当前人工关系的端点、类型和条件说明；不会发送关系记录人或历史审计。关系不额外触发模型调用；离线仍只做摘编。API与人工身份认证边界保持原状。

新增接口（前缀`/api/literature-workspace/`）：

| 方法与路径 | 用途 |
|---|---|
| GET projects/{id}/relations | 当前关系、过期状态和修订历史 |
| POST projects/{id}/relations | left/right、source_revisions、kind、actor、note，创建关系 |
| POST projects/{id}/relations/{relation} | 携带revision重新核对或修改 |
| POST projects/{id}/relations/{relation}/delete | 携带revision移除 |
| GET projects/{id}/audit | 同一数据库读取快照下的写作结构检查 |
| GET projects/{id}/audit/export?format=json/markdown/csv | 导出证据与核对记录；JSON/Markdown含关系，CSV为逐证据表 |

新增`evidence_relations`表，单个专题最多60条关系，旧库启动时兼容建立。导出记录包含生成时刻、上下文指纹、来源版本/哈希及Unicode位置；CSV为UTF-8 BOM，并保护表格公式前缀。审计导出是请求时的当前状态；如需固定留档，应保留下载文件。SQLite备份同时保留关系。

仍未完成真实跨领域盲评、自动来源抓取/OCR、自动语义冲突检测或多用户权限。页面中的关系与就绪提示不能作为引用支持率、专家质量评分或多智能体效果提升的证据。


## 公开标注与独立盲评工具

研究CLI固定SciFact生物医学与QASPER NLP各10篇/30样本，验证原数据包及文献/标注哈希，提供词法基线、实际模型适配器的单次/分阶段调用、分领域指标与双人盲评包。语料保存在本地缓存；模型请求不给gold标签或答案。已以Qwen3-0.6B Q8_0 CPU完成60次单次请求与120次分阶段请求，保留实际输出、usage和耗时；分阶段没有显示稳定质量优势。120项双人盲评材料已生成，人工评分仍为空。此处评估的是证据选择、论断支持与论文问答子任务，不是生产工作区完整综述的质量证明。数据归属、预算、命令与实测见[真实资料评测](RESEARCH_EVALUATION.md)，D13-05仍在进行中。

首页“跟着做一遍”提供7步实际操作：专题、材料、证据、文献对照、写作检查、引用核对和发布导出。引导不自动生成或核对科研结论，虚构教学材料有明确标记。详见[功能体验引导](EXPERIENCE_GUIDE.md)。

## 开放论文体验与统一API

引导可填入科研可视化专题，并从seaborn/ArviZ两篇JOSS正式论文填入元数据与PDF提取正文。文本总长小于现有24000字模型输入上限；图像与原PDF版式未提供，论文研究条件需自行核对。两篇分别导入、筛选和审核，不自动制造文献关系或确认引用。模型调用共用总览配置，正在执行的任务及并行节点固定同一配置。详见[开放案例](OPEN_EXAMPLES.md)和[模型设置](MODEL_SETUP.md)。

# 实施任务清单

基准日期：2026-10-19。本清单保留最初的规划任务与依赖。D01 已交付本机工作区首版，覆盖文档入库、版本与动态索引、可选模型/嵌入、草案编辑审核、导出和评估工具。D01-05 的独立保留集与工艺语义质量评测尚未完成；共用 FastAPI/ORM、独立 worker 与权限仍待后续迁移。当前范围见 [D01说明](D01_WORKSPACE.md)，下表工时为原规划估计，不能当作实际投入。

任务来自 [参考调研与完善计划](RESEARCH_AND_ROADMAP.md)。小时为开发估算，不包含 25% 缓冲。P0 为共用基础，P1/P2 为交付顺序；每项独立通过完成条件再进入发布。

共用层主要落点：计划新增 `backend/`（API/领域服务/仓储）、`worker/`（队列/节点执行）、`migrations/`；`shared/product/` 负责渐进界面改造。项目特有页面和指南继续保留在对应 `demos/` 目录。目录仅为建议，尚不存在时不表示遗漏。

## 执行与范围规则

任务完成前保持 planned 或 in_progress，不以页面数量、代码行数或模拟结果替代完成条件。跨项目共用的能力只估算一次；项目任务包含其适配和验收。新增范围需写明估算增量，不从既有任务中静默挤占。

C06 的主题状态稿与 C01/C02 同期开始；每个项目第 04 项可在第 01 项产出对象后并行准备界面，再与功能联调。评估和集成任务依赖该项目的前四项，不能仅凭前端状态稿标记完成。

建议先执行 C01、C02 与 D09 的一个纵向切片，随后补齐任务/权限/部署门槛。D12-03 的硬件 spike 和 D11-01 的运行器 spike 可提前，但不因此跳过正式依赖。

所有新增依赖继续维护共用 Conda 环境与运行清单。Docker 部署是主要入口；外部视觉推理与独立修复 runner 不改变六个业务模块共用环境的约定。

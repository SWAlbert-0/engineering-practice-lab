# 六项目功能体验引导

## 测试与修复：自动衔接的案例体验

D11 首页点击“一键导入案例并开始”，自动打开平均值精度修复案例并填好离线表单。按蓝色边框操作即可；当前步骤显示一张简短说明卡，无关区域覆盖浅灰蒙版并限制鼠标、键盘操作。当前需要核对的测试或代码保持可读。点击“退出体验”或按 Escape 随时恢复自由操作。

流程为：两轮修复任务 → 第一轮失败用例与日志 → 第二轮修订 → 测试变化与代码差异 → 人工审查 → 单轮对照任务 → 保存两次运行对照 → 下载 Markdown。引导等待真实运行结束再推进；审查表单填入教学示例，使用者可修改并亲自提交。下载响应成功后才显示完成。

引导只绑定本次体验创建的两个任务，不会误用其他最近记录。刷新可自动续接；退出后可继续已有体验或重新开始。新任务、审查与对照保存均由使用者点击；不会自动调用模型。失败时停在当前步骤，保留退出与重新检查入口。进度在浏览器保存，任务与报告在服务端保存。

`tests/test_repair_tour_browser.py` 在 1440px 和 390px 浏览器中覆盖完整真实流程、提交失败恢复、刷新续接、蒙版/键盘限制、审查编辑及实际文件下载。默认测试地址为独立环境 `http://127.0.0.1:8766`，可用 `LAB_TEST_URL` 覆盖。

## 需求设计台：从案例导入到发布导出

D09 首页点击“一键导入案例并开始”，自动填入 RealWorld 登录接口的一段需求。沿用 D11 的单步提示卡、35% 不透明度浅灰蒙版、下一步按钮边框与键盘限制。当前原文、用例或检查结果保持清晰；随时点击退出或按 Escape 返回自由操作。

完整路线：保存需求 → 离线规则分析 → 完善成功登录、认证失败、字段无效三条用例并分别保存新版本 → 追踪矩阵 → 定位原文 → 结构检查 → 人工核对 → 发布当前版本 → 下载发布 JSON。规则将状态码识别成边界的场景在引导中修正为字段异常，不将规则草案直接冒充可发布结果。

自动填入的账号与密码是虚构教学数据，接口预期取自仓库中 MIT 许可的 RealWorld 中文选译。体验不调用模型，不访问真实登录接口。修改使用原编辑器的自动草稿与版本冲突检查；审批、发布门禁保留。核对、发布和导出均需使用者实际点击，下载成功后才完成体验。

体验只关联本次文档、分析任务、用例集与发布记录。刷新恢复草稿时保留使用者修改；刷新核对窗口后回到“核对所选用例”，重新确认本次选择。请求失败停在当前步骤，可重新检查或退出。`tests/test_requirements_tour_browser.py` 覆盖 1440px、390px、完整发布导出、失败恢复、刷新、退出续接及操作限制。

## 项目十三、项目一和项目二：完整自动衔接

这三个项目改用共用的 `shared/product/guided-tour.js` / `.css`，各自的 `tour.js` 定义实际业务步骤。入口为“一键导入案例并开始”，沿用 35% 浅灰蒙版、下一步按钮边框、当前证据可读、鼠标/键盘限制、退出、续接与失败重试。引导绑定本轮记录，不依赖“最近一条”。后台任务完成后才推进，下载响应成功后才显示完成；保存、审核、发布和部署仍由使用者点击。

- **D13 文献研读室**：建立并确认专题提纲 → 导入 seaborn、ArviZ 两篇论文的 Summary 节选（如实标为阅读摘记）→ 逐篇筛选 → 离线摘录 → 打开原文 → 六条证据逐条核对 → 文献对照与有条件的证据关系 → 写作前检查 → 离线章节编排 → 人工修订提交 → 引用核对 → 发布并下载 Markdown、BibTeX、证据 JSON。重复导入可以复用已解析版本，不会因没有新解析任务而卡住。
- **D01 工艺资料台**：导入 Generic PLA 开放材料 → 建立索引 → 限定本次材料检索 → 原文定位 → 离线草案 → 修订保存新版本 → 逐工序核对 → 导出来源和审核记录。启用嵌入 API 时先提示退出核对设置，不暗中改变供应商或发送资料。案例参数不构成生产批准。
- **D02 模型发布平台**：导入 Iris → 两次真实训练、人工审核和加载 → 各自真实预测 → 导入合成特征偏移窗口 → 窗口评估与告警记录 → 明确确认后手工回滚首个版本 → 再次预测校验实际模型 → 导出 JSON 权重及血缘。重复使用教学数据不代表独立业务质量，漂移不会自动触发回滚。

案例文件按清单校验 SHA-256；文本行尾规范化为 LF 后校验，以兼容 Windows 检出。D13 只导入明确范围的节选，不把节选称作全文阅读。D02 部署和回滚的确认框需使用者勾选。

`tests/test_guided_tours_dom.cjs` 连接真实本地服务验证三条完整 DOM/HTTP 链路，包括实际训练、版本门禁、遮罩事件拦截和文件内容；不验证浏览器布局。`tests/test_guided_tours_browser.py` 为 1440px 和 390px 原生浏览器复跑提供完整检查，已接入容器 CI。本次环境无法启动浏览器驱动，原生浏览器的截图与布局检查尚未在本机执行。

## 视频观察台：手动步骤引导

启动任一共用部署环境后，打开项目首页，点击 **“跟着做一遍”**。桌面展示当前操作和全部步骤，手机可展开步骤表；每步都说明“做什么”和“应该看到什么”。点击“打开本步功能”进入实际工作页，“定位操作位置”将滚动并突出显示相应控件。

第一次可以使用离线模式和开放案例，不需要模型密钥。引导卡片显示来源、许可、固定版本、下载入口和“一键填入案例”；先填表，再亲自提交。D13第一步填专题设置、第二步选择两篇开放论文分别导入；D02的三份派生监控窗口与Iris训练的4个特征对应。详见[案例来源与许可](OPEN_EXAMPLES.md)。各项目仍有选题介绍窗口及需求分析、架构、代码入口、任务流程等六章图文指南，可从“完整图文指南”进入。

| 项目 | 步数 / 参考时间 | 起点和完整体验 |
|---|---|---|
| D01 工艺资料检索 | 自动衔接 / 约5分钟 | 开放资料入库、限定检索、原文定位、草案修订、逐工序核对与导出 |
| D02 模型发布平台 | 自动衔接 / 约8分钟 | 两次真实训练和加载、预测、合成偏移窗口、告警处理、手工回滚与导出 |
| D09 需求设计台 | 自动衔接 / 约5分钟 | 使用上文的新案例体验，逐条完善用例、核对来源、审核发布并导出 |
| D11 测试与修复 | 自动衔接 / 约5分钟 | 使用上文的新案例体验；每次执行、审查与导出均高亮引导 |
| D12 视频观察台 | 6 / 6–10分钟 | 导入实际教学视频、服务端固定采样、点击帧跳回原片、保存离线采样记录、回看/可选模型证据核对、下载并改变采样 |
| D13 文献研读室 | 自动衔接 / 约8分钟 | 两篇节选、六条逐字证据、条件关系、离线编排、章节修订、引用核对及三类发布导出 |

页面跳转到最近的真实业务记录；还没有记录时先进入列表或创建页。若你切换到另一条记录，请以实际选中的任务、专题和版本为准。创建、训练、运行、审核和发布仍由你在业务页面明确操作，引导不会自动代做。

完成一项后，亲自检查预期现象，再点击“已看到预期结果，下一步”。进度只保存在当前浏览器，并明确标为“自行确认”；刷新可继续，也可收起或重新体验。它不是服务端验收状态，不替代测试、证据审核、真实模型质量或课程评分。

D11完整Docker隔离执行需要可用Docker与worker；Conda/venv只运行既有可信教学候选。D12需要FFmpeg/ffprobe，Docker与Conda已包含。D13原教学文本仍标为虚构，新开放论文案例注明作者、DOI与提取范围；离线阅读/写作仅摘录编排；D12离线记录没有视觉回答。需要真实模型时先按[模型配置](MODEL_SETUP.md)配置，再明确选择模型模式。

# 六项目功能体验引导

## 测试与修复：自动衔接的案例体验

D11 首页点击“一键导入案例并开始”，自动打开平均值精度修复案例并填好离线表单。按蓝色边框操作即可；当前步骤显示一张简短说明卡，无关区域覆盖浅灰蒙版并限制鼠标、键盘操作。当前需要核对的测试或代码保持可读。点击“退出体验”或按 Escape 随时恢复自由操作。

流程为：两轮修复任务 → 第一轮失败用例与日志 → 第二轮修订 → 测试变化与代码差异 → 人工审查 → 单轮对照任务 → 保存两次运行对照 → 下载 Markdown。引导等待真实运行结束再推进；审查表单填入教学示例，使用者可修改并亲自提交。下载响应成功后才显示完成。

引导只绑定本次体验创建的两个任务，不会误用其他最近记录。刷新可自动续接；退出后可继续已有体验或重新开始。新任务、审查与对照保存均由使用者点击；不会自动调用模型。失败时停在当前步骤，保留退出与重新检查入口。进度在浏览器保存，任务与报告在服务端保存。

`tests/test_repair_tour_browser.py` 在 1440px 和 390px 浏览器中覆盖完整真实流程、提交失败恢复、刷新续接、蒙版/键盘限制、审查编辑及实际文件下载。默认测试地址为独立环境 `http://127.0.0.1:8766`，可用 `LAB_TEST_URL` 覆盖。

## 其他五个项目

启动任一共用部署环境后，打开项目首页，点击 **“跟着做一遍”**。桌面展示当前操作和全部步骤，手机可展开步骤表；每步都说明“做什么”和“应该看到什么”。点击“打开本步功能”进入实际工作页，“定位操作位置”将滚动并突出显示相应控件。

第一次可以使用离线模式和开放案例，不需要模型密钥。引导卡片显示来源、许可、固定版本、下载入口和“一键填入案例”；先填表，再亲自提交。D13第一步填专题设置、第二步选择两篇开放论文分别导入；D02的三份派生监控窗口与Iris训练的4个特征对应。详见[案例来源与许可](OPEN_EXAMPLES.md)。各项目仍有选题介绍窗口及需求分析、架构、代码入口、任务流程等六章图文指南，可从“完整图文指南”进入。

| 项目 | 步数 / 参考时间 | 起点和完整体验 |
|---|---|---|
| D01 工艺资料检索 | 6 / 8–12分钟 | 从引导下载教学Markdown并上传；检索原句、核对条件、形成草案、逐工序修改/审核、导出，再替换资料观察来源过期 |
| D02 模型发布平台 | 6 / 10–15分钟 | 创建种子42教学数据、训练、审核加载、发起实际预测、比较干净/偏移/无标签窗口、处理告警并体验历史回滚 |
| D09 需求设计台 | 6 / 8–12分钟 | 填入考勤样例并保存、规则分析、修改用例草稿并提交版本、追踪原文、人工审核、发布导出与需求变更 |
| D11 测试与修复 | 自动衔接 / 约5分钟 | 使用上文的新案例体验；每次执行、审查与导出均高亮引导 |
| D12 视频观察台 | 6 / 6–10分钟 | 导入实际教学视频、服务端固定采样、点击帧跳回原片、保存离线采样记录、回看/可选模型证据核对、下载并改变采样 |
| D13 文献研读室 | 7 / 12–18分钟 | 创建专题、导入材料并筛选、阅读与证据核对、文献/证据关系对照、写作前检查、论述支持核对、发布导出及来源变化 |

页面跳转到最近的真实业务记录；还没有记录时先进入列表或创建页。若你切换到另一条记录，请以实际选中的任务、专题和版本为准。创建、训练、运行、审核和发布仍由你在业务页面明确操作，引导不会自动代做。

完成一项后，亲自检查预期现象，再点击“已看到预期结果，下一步”。进度只保存在当前浏览器，并明确标为“自行确认”；刷新可继续，也可收起或重新体验。它不是服务端验收状态，不替代测试、证据审核、真实模型质量或课程评分。

D11完整Docker隔离执行需要可用Docker与worker；Conda/venv只运行既有可信教学候选。D12需要FFmpeg/ffprobe，Docker与Conda已包含。D13原教学文本仍标为虚构，新开放论文案例注明作者、DOI与提取范围；离线阅读/写作仅摘录编排；D12离线记录没有视觉回答。需要真实模型时先按[模型配置](MODEL_SETUP.md)配置，再明确选择模型模式。

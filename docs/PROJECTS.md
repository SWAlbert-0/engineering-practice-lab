## D01：基于 RAG 的轻量级企业工艺生成

**用途**：依据实际工艺文档检索证据，形成可编辑、可核对并导出的草案。

**当前首版**：TXT/Markdown/文本型 PDF 入库与版本、动态 BM25/LSA 索引、可选预训练嵌入、证据原页定位、离线/模型草案、逐工序核查、版本冲突与来源过期门禁、JSON/Markdown 导出、批量检索评估。文档与记录保存于 SQLite，Docker 使用命名卷。

**演示流程**：上传资料 → 检查解析索引任务 → 检索与核对原文 → 生成草案 → 保存修改版本 → 逐工序核查 → 导出。替换或删除来源后验证旧草案不可通过审核。

**代码入口**：`shared/process_workspace.py`、`scripts/parse_process_pdf.py` 与 `demos/02-process-rag/workspace.js`。旧 `engine.py` / `/api/rag` 仅为固定语料基线。

**边界与后续**：本机单工作区，不提供账户或企业审批；OCR、复杂表格、独立工艺保留集和真实模型质量评测仍需完成。存储、备份、接口与运行说明见 [D01工作区说明](D01_WORKSPACE.md)。

## D02：基于 MLOps 的全链路 AI 模型部署与监控系统

**用途**：串联模型训练、质量评估、发布审批和监控处置。

**当前功能**：实际训练两个逻辑回归模型，计算准确率与 PSI，实验内切换模型重新预测。

**演示流程**：运行实验 → 比较版本与分布 → 检查准入条件 → 模拟审批发布 → 处理告警与回滚。

**实现入口**：`demos/03-mlops/` 下的 `engine.py` 提供核心处理，`product.js` 定义业务页面；浏览器访问 <http://127.0.0.1:8765/demos/03-mlops/>。

**当前边界**：合成数据；发布审批、流量和告警为本地流程，尚未接入真实注册中心或服务。

**后续开发与评估**：接入模型注册与推理服务，落地版本和指标存储；评估发布可追溯性、监控延迟与回滚正确性。

## D09：基于大模型 API 的智能需求分析与用例生成工具

**用途**：保存可修订需求，形成有原文依据、可人工审核和发布的测试用例集。

**当前功能**：TXT/Markdown 与粘贴导入、段落偏移与原文版本、持久分析任务、规则或模型结构化用例、服务端自动草稿、冲突比较、用例增删/修订/去重、验收追踪、版本审核、来源变更影响、不可变发布及 CSV/JSON/Markdown 导出回导。

**操作流程**：保存原文 → 生成 → 核对原文与编辑用例 → 提交新版本 → 按所选数量审核 → 发布快照并导出。

**实现入口**：`shared/requirements_workspace.py`、`demos/05-requirements/workspace.js`，由现有 Python 服务适配。旧 `engine.py` 与 `workbench.html` 仅作规则/模板教学基线。

**边界与后续**：本机单工作区，审核身份为填写记录；尚未实现账户权限、ER/UML、自动测试执行或百样例双人语义质量评测。实际限制、备份与 API 见 [D09工作区说明](D09_WORKSPACE.md)。

## D11：基于大语言模型智能体的自动化软件测试与缺陷修复系统

**用途**：通过测试验证缺陷与候选修复，保留验收和审查证据。

**当前功能**：固定源码与公开测试快照，持久任务、离线/手写/可选模型候选、最多两次修订；独立 Docker 运行器、每轮 diff/测试/日志、停止恢复、补丁导出、审查门禁与冲突检测。

**操作流程**：选择快照 → 复现 → 提议与有限修订 → 回归/独立验收 → 对照差异与日志 → 人工审查 → 导出补丁。

**实现入口**：`shared/repair_workspace.py` 管理任务/证据，`repair_runner.py` 管理受限容器，`scripts/repair_worker.py` 为独立入口；项目 `workspace.js` 提供页面。旧 `engine.py`/`workbench.html` 作为可信教学基线保留。详细信息见 [D11说明](D11_WORKSPACE.md)。

**当前边界**：三个原创单函数快照，无任意仓库或 shell。Conda/venv 只执行内置可信候选；Docker 支持经约束的手写/模型候选。人工记录未认证身份。

**后续开发与评估**：接入授权仓库及固定提交/依赖镜像，完成5仓库/30缺陷独立评测，比较同模型单轮与有限循环的解决率、回归破坏和成本。

## D12：轻量级多模态大模型的视频理解与推理系统

**用途**：通过视频采样与视觉问答建立可核查的时间证据。

**当前功能**：浏览器实际预览与抽帧，时间戳校验、分析记录，以及可选视觉模型 API 问答。

**演示流程**：选择样片或本地视频 → 抽取采样帧 → 检查时间线 → 离线校验或模型问答 → 保存证据记录。

**实现入口**：`demos/04-video-understanding/` 下的 `app.js`、`engine.py`、`sample.webm` 提供核心处理，`product.js` 定义业务页面；浏览器访问 <http://127.0.0.1:8765/demos/04-video-understanding/>。

**当前边界**：离线模式不理解画面；尚未部署本地轻量模型，也未完成两基准或效率精度实验。

**后续开发与评估**：部署轻量多模态模型，设计采样与推理策略；比较至少两套基准的准确率、延迟、显存和失败类型。

## D13：基于多智能体协同的科研文献智能综述生成系统

**用途**：围绕研究问题组织文献证据，经角色协作形成可审查的综述草稿。

**当前功能**：五篇论文摘要摘记，离线、单次综合与并行阅读模式，引用位置检查和人工审核。

**演示流程**：选择问题与摘记 → 运行阅读和综合流程 → 核查引用位置 → 逐条人工审核 → 确认整篇草稿。

**实现入口**：`demos/06-literature/` 下的 `engine.py`、`papers.json` 提供核心处理，`product.js` 定义业务页面；浏览器访问 <http://127.0.0.1:8765/demos/06-literature/>。

**当前边界**：处理的是人工摘要转述，尚未解析全文；引用位置匹配不表示语义支持或综述质量已达标。

**后续开发与评估**：接入全文与检索、任务状态和失败恢复；用单模型基线及跨子领域盲评衡量引用支持、覆盖与综合质量。

## 共用能力与数据保存

- 每个项目有独立主题、选题介绍弹窗及需求分析、架构设计、代码开发、任务流程、验收与排查、后续开发六章图文指南。
- D01 和 D09 使用服务端 SQLite；其余四项仍保存在浏览器 LocalStorage。当前不具备多用户工作区隔离。
- 工艺、需求、修复、视频与文献可显式选择模型模式；修复模型源码只在独立 Docker 运行器执行。配置只留在服务端，MLOps 使用本地机器学习计算。
- Docker 统一应用环境，D11 另有独立运行器与受限任务容器。容器部署与 MLOps 页面中的模拟模型发布是不同能力。

# 项目页面与交互流程

更新：2026-10-02。四个项目的入口保持不变，使用独立导航和 hash 路由。所有项目仍共用根目录 Conda 环境，不增加安装步骤。

## 通用行为

- 导航可返回概览、列表与详情；页头可切换项目。
- 列表支持按当前行文本筛选，未匹配时有空状态。
- 表单使用必填校验，提交期间锁定按钮；失败时显示原因。
- 记录写入当前浏览器 LocalStorage，各项目独立存储；设置页可导出 JSON 和重置。
- 初始示例单独标记。真实计算结果经同源 iframe 消息传入项目页面并保存；拒绝其他窗口或不同来源的结果消息。
- 存储不可用或超出容量时明确提示，当前会话仍可继续，建议导出备份。
- 页面采用四套独立响应式主题；已通过 Firefox 桌面与窄屏检查，尚未做手机硬件实测。各项目顶部“选题介绍”可查看题目要求、评分、风险和实现范围。

## 测试与修复

页面：概览、仓库列表/登记/详情、任务列表/新建/详情、测试工作台、执行列表/详情、补丁审查、规则、设置、指南。

任务流程：

1. 在教学仓库创建任务，填写预期行为，选择内置缺陷与候选。
2. 打开执行工作台，运行 Python 测试。
3. 自动保存原始测试、补丁差异、回归与独立用例结果。
4. 通过的补丁可认可或退回；未通过的补丁不能认可。可保存审查备注、导出结果。

任务状态：待运行 → 已验证 / 验收失败。每次执行独立留档，重新运行不会覆盖历史结果。

仓库地址是管理信息，不触发网络访问或拉取代码。人工审查不会创建 PR 或合并远程代码。规则页中的自动验收标准固定；人工审查人和要求可编辑。

## 工艺资料检索

页面：概览、知识库、文档列表/导入/详情、检索工作台、检索记录/详情、草案列表/编辑审核、评估列表/详情、设置、指南。

检索与审核流程：

1. 查看知识库中的8段内置资料与版本，按材料发起检索。
2. 检索记录保留问题、模式、引用、分数与拒答结果。
3. 有依据的结果可保存为草案；重复保存会打开已有草案。
4. 修改草案后重新进入待审核，审核人可以通过或退回，并保存意见。
5. 固定问题评估会实际调用4次接口，检查3个首条命中与1个拒答场景。

导入支持粘贴文本或 UTF-8 .txt 文件（100 KB以内），资料详情可预览和导出。新增文本仅在浏览器保存，不参与服务端索引。审核通过是本地流程记录，不代表企业生产审批。修改草案不会自动验证引用支持关系。

## 模型发布平台

页面：概览、数据集列表/结构、实验列表/运行/详情、版本列表/详情、发布列表/创建/详情、监控窗口、告警列表/处理、设置、指南。

实验与发布流程：

1. 查看训练、验证与当前窗口的用途，运行实际逻辑回归训练。
2. 保存实验参数、准确率、PSI、预测样本和数据标识，同时生成 v1/v2 版本记录。
3. 质量下降的 v2 或没有当前真实标签的 v2 不能进入发布审批。
4. 选择合格版本，填写环境、模拟流量比例与变更说明。
5. 审批后进入“模拟发布中”，可记录“已模拟回滚”。这些状态不会更改真实推理服务。
6. 监控页展示最近一次实验快照；质量下降、漂移或无标签会产生本地告警，填写结论后标记已处理。

实验内回滚会实际使用 v1 重新预测。发布页是另一套本地流程状态，未连接 MLflow、容器或真实流量。当前只保存指标与记录，不保存模型权重。

## 塔防工作室

页面：大厅、关卡列表/详情、游玩、图鉴、布阵列表/详情/编辑、战绩列表/详情、设置、指南。

关卡共用道路与五波敌人，区别在初始资源：

| 关卡 | 金币 | 基地耐久 |
|---|---:|---:|
| 基础训练 | 240 | 20 |
| 标准防线 | 160 | 12 |
| 紧缺补给 | 130 | 10 |

布阵与战斗流程：

1. 在编辑器选择关卡，用地图工具放置或移除弩塔、霜塔；可撤销最后一座或清空。
2. 放置时检查道路、边界、塔间距离和金币；保存时再次检查所选关卡预算。
3. 在布阵详情选择“使用此布阵开局”，游戏按同样规则加载塔位。
4. 可设置1、1.5或2倍速，以及是否显示建造预览。进入关卡后生效。
5. 胜利或失败后自动保存金币、耐久、击杀、波次、逻辑时间和结束塔位；离开未完成对局不计成绩。

布阵编辑器不编辑道路、寻路和波次；没有塔升级、音效或账号系统。重开会恢复本关初始资源，并重新加载开局布阵。

## 开发结构

- `shared/product/core.js`：路由、页面组件、存储、表单事件与工作台消息桥接。
- `shared/product/style.css`：公共组件；`themes.css`、`themes.js`：独立主题与首页；`topics.js`：选题介绍数据。
- 各项目 `product.js`：页面定义、初始数据与操作流程。
- 各项目 `workbench.html`、`app.js`：实际计算或游戏界面。
- 原 Python 引擎与接口保持原有职责，Windows UTF-8 修复继续生效。

验证命令与边界见 `VALIDATION.md`。新增页面没有引入前端框架、构建工具或额外运行依赖。

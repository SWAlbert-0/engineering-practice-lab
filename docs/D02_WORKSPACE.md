# D02 模型发布与监控工作区

D02 将单次合成实验扩展为数据、训练、模型制品、真实预测、发布/回滚和监控的持久工作区。入口为 `/demos/03-mlops/`。当前为本机单实例首版，默认无需模型密钥或外部服务。

## 完整流程

1. 导入有权使用的 UTF-8 CSV，明确训练/监控用途及标签列。也可生成明确标注的合成教学材料。当前只支持1–12个数值特征与0/1二分类。
2. 检查行数、列名、标签、缺失/无效值和重复特征行。数据修订创建新的不可变快照，保存父快照与原文件哈希；归档不删除历史训练依据。
3. 创建实验，固定 C、随机种子、最低准确率与最高 Log Loss。数据按75%/25%分层随机切分，保存实际行索引，标准化只使用训练部分。
4. 后台训练逻辑回归，保存均值、尺度、系数、截距、分类阈值和训练参考分箱。重新载入 JSON 参数，核对验证准确率一致后保存结果。
5. 核对混淆矩阵、指标、数据来源、切分与适用范围，记录人工审核。门禁未通过的模型不能获批；审核人是文本署名，不等同账户认证。
6. 发起发布任务，确认目标、特征结构和影响范围。加载时校验 JSON、哈希、审核修订和真实推理探针；活动修订仍一致才原子切换指针。失败保留原模型并记录原因。
7. 在预测服务输入 JSON 对象数组，响应包含实际 `model_id`、`deployment_revision`、`artifact_sha`、概率与请求标识。每行按特征名校验，不根据列顺序猜测。
8. 选择监控数据创建窗口，查看输入质量、标签覆盖、特征分布、效果与告警。需要回滚时单独选择曾成功加载、仍获批准的历史制品，加载后再次实际预测验证。

## 核心实现与数据

| 对象 | 记录内容 |
|---|---|
| 数据快照 | 原始CSV、哈希、父快照、列结构、行数据、标签和质量统计 |
| 训练实验 | 数据ID、参数、质量门禁、训练/验证行索引、实际指标、耗时 |
| 模型制品 | 仓库训练脚本产生的线性JSON参数、SHA-256、审核记录 |
| 加载任务与事件 | 目标/实际模型、活动修订、操作者、依据、成功/失败及耗时 |
| 预测请求 | 实际模型、修订、结果计数、有限概率样本、错误与计算耗时 |
| 监控窗口 | 固定数据、模型、上一模型、阈值、有效/标签行数及原始分箱计数 |
| 告警与处理 | 窗口、规则、级别、处理修订、处理人、依据与完整操作历史 |

领域与存储为 `shared/mlops_workspace.py`，模型训练为 `scripts/train_mlops.py`。训练只执行仓库自带脚本，不执行上传代码，不接受任意 pickle/模型上传。POSIX 下训练子进程限制约1.5 GiB地址空间与35秒CPU时间，父进程50秒墙钟超时；Windows使用父进程超时，不提供POSIX资源限制。BLAS/OMP限制为单线程。

任务保留输入、状态、心跳和结果；服务退出后旧运行任务标记中断，需显式重试，不自动重新发布。训练串行执行，网页关闭不取消任务。活动指针和成功事件在同一事务中提交；正在处理的请求可以返回开始时选择的旧修订，这会在响应中明确标识。

数据、原文件、模型参数及记录均保存于 `LAB_DATA_DIR/mlops.sqlite3`。Docker为 `/data/` 命名卷，本地默认 `data/`。旧 `engine.py`、`workbench.html`、`product.js` 与 `/api/mlops` 留作教学兼容基线，旧LocalStorage记录不自动升级为实际模型部署。

## 监控的含义

当前窗口是显式导入的快照，**不是持续生产流量采集**。

- 输入质量：统计缺失/无效特征、无效标签、重复特征行；缺失或无效特征行不参与预测，原始总行数和跳过行数可见。
- 漂移：每个特征沿用该模型训练子集的分位数边界，用0.5计数平滑计算PSI。图中柱高为各自频率，保留原始计数和边界。默认0.2阈值为教学规则，需业务校准。
- 效果：准确率只用确实有0/1标签的有效行计算。有效行、标签行数和标签覆盖率同时达标后，才触发质量下降告警。完全无标签时准确率为 `null`。
- 同窗口基线：上一加载模型的特征兼容、制品可用时，对同一批有效且有标签的行预测；不把不同数据集的验证分数冒充同窗口差值。
- 处置：漂移、样本不足、标签不足与效果下降分别产生告警。关闭告警只记录人工处理，不改变原窗口，也不会自动回滚。

教学方案包括干净窗口、第一特征偏移、标签翻转、无标签、特征缺失。它们便于验证规则，不代表真实业务分布或模型泛化能力。改变服务版本不改写旧窗口，页面会标注历史窗口。

## 可选 MLflow 与指标出口

默认部署不要求 MLflow。配置服务端 `LAB_MLFLOW_URL`，可选 `LAB_MLFLOW_EXPERIMENT`（默认 `engineering-practice-lab`）和 `LAB_MLFLOW_TOKEN`，重启后可在实验详情显式同步。

`shared/mlops_tracking.py` 使用MLflow REST同步实验参数、验证指标、数据/制品哈希和本地ID，保存远端 run ID，重试优先复用已关联 run。不会发送原始CSV或权重，不跟随携带凭据的重定向，不把供应商错误正文或密钥回显到页面。创建响应丢失时会按本地实验标签搜索远端；若远端出现重复run，要求先核对，不继续扩散重复。

此桥接是**实验元数据追踪**。外部MLflow模型注册、权重上传和别名同步尚未实现；本地模型表负责当前受信制品管理。外部run状态不控制预测服务。MLflow不可达不影响已保存实验或当前服务。

`GET /api/mlops-workspace/metrics` 提供Prometheus文本格式的真实累计请求、错误、预测行数、计算耗时总和、活动修订与即时制品就绪状态。不包含高基数模型/请求ID标签。计算耗时涵盖模型读取、输入校验与推理，**不含审计写入与网络往返**；它不是端到端HTTP延迟。本版未默认部署Prometheus/Grafana，也未接Evidently报告。

接口参考：[MLflow REST API](https://mlflow.org/docs/latest/api_reference/rest-api.html)、[Prometheus文本格式](https://prometheus.io/docs/instrumenting/exposition_formats/)。

## 运行与备份

全部选题继续共用一套 Docker / Conda / venv 环境，新增功能无默认运行依赖变更。三种方式见 [README](../README.md)。Docker更新：

```bash
git pull
docker compose up --build -d --wait --wait-timeout 90
```

使用SQLite backup API创建一致性备份：

```bash
# 在项目共用环境中执行
python scripts/backup_process_data.py --project mlops --output backups/mlops.sqlite3

# 容器内备份，再复制到宿主机
docker compose exec lab python scripts/backup_process_data.py --project mlops --output /data/backups/mlops.sqlite3
docker compose cp lab:/data/backups/mlops.sqlite3 ./mlops-backup.sqlite3
```

输出路径必须不存在。恢复前停止应用，将备份替换到对应数据库，移除该库旧 `-wal`/`-shm`，保持UID/GID10001可读写，再启动。模型权重和活动指针都在同一份备份内；恢复覆盖当前工作区，先保存现有数据。

## 限制与后续评估

单文件4 MiB、最多10000行/12特征，训练至少40行且每类至少4行；最多100个有效数据快照，历史原文件合计128 MiB。实时预测每次1–1000行。数据必须有限且特征绝对值不超过1000000。监控允许缺失特征和标签并明确统计，训练不允许缺失。请求保留最近2000条与每次前5条输出样本，累计计数独立保存；不保存完整在线输入。

当前不含多租户、实时共同编辑、百分比灰度、多实例编排、Kubernetes、自动重训练或数据流持续采集。随机验证切分不保证业务无泄漏；重复行会提示，但时间泄漏和任务适配需要人工检查。

工程验收覆盖100次实际版本请求、加载失败保留旧模型、审核/活动指针冲突、历史权重回滚、重启恢复、五种窗口及告警审计。真实业务留出集、Evidently对照、阈值/误报校准、持续数据流、外部MLflow实机服务和固定硬件的并发负载基准仍待完成。不能把教学窗口的准确率或单次计算耗时用作生产性能成绩。

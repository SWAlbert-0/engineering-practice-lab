# 测试与修复

来源：丁箐 项目十一。

## 运行

在仓库根目录启动，全部项目共用同一个环境：

```powershell
# Windows PowerShell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

```bash
# macOS / Linux
bash start.sh
```

脚本优先使用当前终端可调用的 Conda，自动创建/复用 `engineering-practice-lab`。无 Conda 时需要 Python 3.10–3.13（推荐3.12），自动创建共用 `.venv`。无需先手动激活，首次安装后会直接启动服务。

访问 `http://127.0.0.1:8765/demos/01-repair-agent/`。环境、端口与检查参数见 [完整部署说明](../../docs/DEPLOYMENT.md)。请通过本地服务访问所有项目功能。

## 演示步骤

选择缺陷 → 选择正确/错误候选 → 运行 → 检查diff和测试 → 导出JSON。

## 本次实现

AST解析、三类缺陷、可信独立进程测试、候选补丁diff、回归和独立验收、失败拒绝。

## 当前边界

候选提供器是离线fixture，不是LLM；没有任意仓库、容器安全隔离、覆盖率或5个开源项目评测。

## 完整项目下一步

先增加LLM提供器与严格补丁schema；保持测试只读；隔离容器禁网和资源配额；至少5个开源项目/3类缺陷；比较同模型单轮基线，测解决率、回归破坏率、预算和覆盖率。


## 项目页面与记录

仓库 → 修复任务 → 测试工作台 → 执行详情 → 补丁审查。

仓库登记和任务说明只作为本地管理信息。执行工作台使用选定的内置缺陷，不读取登记的远程仓库。每次实际测试结果会进入执行记录；自动验收通过的补丁可以进入人工审查，支持认可、退回和备注。

项目入口是 `index.html`；原计算或游戏页面保留为 `workbench.html`，由项目入口嵌入。新增记录保存在当前浏览器，可在设置页导出或重置，不会自动同步到其他设备。

# 测试与修复

原选题：**D11 · 基于大语言模型智能体的自动化软件测试与缺陷修复系统**（丁箐老师）。目录编号与原题编号不同。

用途、实际能力和后续评估见 [六个选题说明](../../docs/PROJECTS.md)。项目内提供选题介绍弹窗和六章图文指南。

## 容器启动

安装并启动 Docker（Windows/macOS 使用 Docker Desktop 的 Linux 容器），在仓库根目录执行：

```bash
docker compose up --build -d --wait
```

浏览器打开 <http://127.0.0.1:8765/demos/01-repair-agent/>。六个项目共用一个容器，不需要本机 Python、Conda 或 Node.js。首次构建需要联网，默认离线功能无需模型密钥。

日志、更新、端口和可选模型配置见 [部署说明](../../docs/DEPLOYMENT.md)。需要直接修改 Python 代码时，仍可使用其中的共用 Conda 开发环境。

## 演示步骤

选择缺陷 → 选择正确/错误候选 → 运行 → 检查diff和测试 → 导出JSON。

## 本次实现

AST解析、三类缺陷、可信独立进程测试、候选补丁diff、回归和独立验收、失败拒绝。

## 当前边界

候选提供器是离线fixture，不是LLM；没有任意仓库、容器安全隔离、覆盖率或5个开源项目评测。

## 完整项目下一步

先增加LLM提供器与严格补丁schema；保持测试只读；隔离容器禁网和资源配额；至少5个开源项目/3类缺陷；比较同模型单轮基线，测解决率、回归破坏率、预算和覆盖率。


## 项目页面与记录

仓库 → 修复任务 → 测试工作台 → 执行详情 → 补丁审查。

仓库登记和任务说明只作为本地管理信息。执行工作台使用选定的内置缺陷，不读取登记的远程仓库。每次实际测试结果会进入执行记录；自动验收通过的补丁可以进入人工审查，支持认可、退回和备注。

项目入口是 `index.html`；计算页面保留为 `workbench.html`，由项目入口嵌入。新增记录保存在当前浏览器，可在设置页导出或重置，不会自动同步到其他设备。

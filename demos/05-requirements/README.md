# 需求设计台

D09 · 基于大模型 API 的智能需求分析与用例生成工具（丁箐老师）。

面向需求评审和测试设计的本机工作区：导入实际需求，生成结构化用例，逐项完善、审核并发布可追溯版本。文档、草稿和记录保存在服务端，支持不同浏览器读取。

在仓库根目录运行：

```bash
docker compose up --build -d --wait
```

打开 <http://127.0.0.1:8765/demos/05-requirements/>。Docker、共用 Conda 环境和 Python venv 三种方式见 [根目录 README](../../README.md)。没有新增项目专用环境或 Python 依赖。

## 核心功能

- UTF-8 TXT / Markdown / 粘贴文本，原文版本、段落与字符偏移固定。
- 离线规则基线；可选模型实际生成需求、验收条件、问题和用例步骤，引用/结构校验失败不入库。
- 原文与用例并排核对，编辑前置条件、步骤、输入、预期及验收关联；新增、删除和完全重复候选合并。
- 服务端自动草稿、刷新恢复、历史版本、双浏览器冲突差异与本地备份。
- 按版本批量审核、需求变更影响、追踪矩阵和受门禁约束的不可变发布快照。
- CSV / JSON / Markdown 导出，JSON 校验回导；导入不会沿用旧审核。
- 选题介绍弹窗、图文指南、桌面和窄屏布局、真实任务状态与重试。

## 运行与边界

默认离线功能无需密钥。模型方式需显式选择，见 [模型配置](../../docs/MODEL_SETUP.md)。单次模型首版最多六段原文，生成结果仍需人工核对。

当前为单工作区，没有账户权限。用例没有自动执行；ER/UML、外部管理系统同步、100 条业务保留集和双人语义质量评估尚未完成。关联率只表示结构关系，已核对不表示测试通过。

完整流程、限制、API、备份与验收见 [D09 工作区说明](../../docs/D09_WORKSPACE.md)。D09 数据库与 D01 共用现有 Docker 数据卷；普通更新保留数据，避免使用 `docker compose down -v`。

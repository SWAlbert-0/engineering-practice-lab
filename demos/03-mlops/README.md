# 模型发布实验

原选题：**D02 · 基于 MLOps 的全链路 AI 模型部署与监控系统**（丁箐老师）。目录编号与原题编号不同。

用途、实际能力和后续评估见 [六个选题说明](../../docs/PROJECTS.md)。项目内提供选题介绍弹窗和六章图文指南。

## 容器启动

安装并启动 Docker（Windows/macOS 使用 Docker Desktop 的 Linux 容器），在仓库根目录执行：

```bash
docker compose up --build -d --wait
```

浏览器打开 <http://127.0.0.1:8765/demos/03-mlops/>。六个项目共用一个容器，不需要本机 Python、Conda 或 Node.js。首次构建需要联网，默认离线功能无需模型密钥。

日志、更新、端口和可选模型配置见 [部署说明](../../docs/DEPLOYMENT.md)。需要直接修改 Python 代码时，仍可使用其中的共用 Conda 开发环境。

## 演示步骤

默认污染0.65运行 → 观察回滚 → 改为0运行 → 特征偏移2运行 → 取消真实标签运行。

## 本次实现

两个真实CPU逻辑回归模型、固定种子、数据hash、独立训练/验证/当前窗口、PSI、同窗口质量比较、活动模型切换和新预测。

## 当前边界

合成数据；只在本次请求内生效，无数据库或模型注册中心；未接DVC、MLflow、Docker、Prometheus/Grafana和CI/CD。坏候选故意绕过发布门禁用于演练。

## 完整项目下一步

补DVC数据版本、MLflow registry/alias、容器API、指标抓取和仪表盘；发布前验证门禁、金丝雀流量；处理标签延迟；回滚后验证服务真正加载对应模型。


## 项目页面与记录

数据集 → 训练实验 → 模型版本 → 发布审批 → 监控窗口 → 告警处理。

每次实际训练生成两个版本记录。质量下降的候选与缺少真实标签的候选不能进入审批。发布审批、流量比例、发布和回滚仅保存为本地流程状态；监控展示最近一次实验快照，非持续采集。模型权重未持久化。

项目入口是 `index.html`；计算页面保留为 `workbench.html`，由项目入口嵌入。新增记录保存在当前浏览器，可在设置页导出或重置，不会自动同步到其他设备。

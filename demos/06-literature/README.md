# 文献研读室

**D13 · 基于多智能体协同的科研文献智能综述生成系统**（丁箐老师）。围绕研究问题组织文献筛选、证据核对、分节写作与发布。

在仓库根目录运行：

```bash
docker compose up --build -d --wait --wait-timeout 90
```

打开 <http://127.0.0.1:8765/demos/06-literature/>。Docker、共用 Conda 与 venv 三种方式见 [仓库 README](../../README.md)，不需要为每个项目单独创建环境。

## 当前能力

- PDF / UTF-8 文本导入、元数据与原文件版本，原文/摘要/摘记范围标记。
- 研究专题、纳入/排除理由，带版本、页码、逐字位置与人工结论的证据矩阵。
- 离线摘编、单次模型与分工阅读/写作；持久节点、取消、中断恢复与失败节点重试。
- 章节编辑、自动草稿、乐观锁冲突恢复、不可变提交、逐条引用核对和发布门禁。
- Markdown、BibTeX、证据 JSON 导出；来源变更使旧草案过期，已发布快照保持不变。
- 独立墨蓝阅读界面、引用原文窗口、选题介绍及六章图文指南，支持窄屏。

使用前先建立专题，再导入、筛选和核对证据。离线流程无需密钥，离线摘编不执行语义综合。教学材料为虚构；旧 `papers.json` 人工摘记及 `engine.py` 保留为兼容基线，不作为新工作区的论文原文。

服务端保存 `literature.sqlite3`，不再将新记录存入 LocalStorage。完整流程、API 对象、限制、模型调用预算、备份恢复和评估计划见 [D13 工作区说明](../../docs/D13_WORKSPACE.md)。尚未实现学术搜索、OCR、参考文献结构解析、账户权限和跨领域盲评；逐字校验不代表语义支持。

```bash
python -m unittest discover -s tests -v
node tests/test_literature_browser.cjs
```

浏览器测试需服务运行及 Playwright 浏览器测试环境；不属于运行依赖。模型协议使用离线桩，实际供应商质量仍待评估。容器 CI 运行浏览器流程、重启持久化和其余项目回归，见 [验证记录](../../docs/VALIDATION.md)。
